# Codele 要件定義書

## 1. プロジェクト概要

**プロジェクト名:** Codele  
**種別:** Webブラウザゲーム（シングルページアプリケーション）  
**コンセプト:** プログラミング・IT用語をテーマにしたWordle風の5文字推測パズルゲーム

プレイヤーは1日1回（またはリトライモード）、5文字のプログラミング関連英単語を最大6回の試行で当てるゲームです。各試行後に色によるフィードバックが与えられ、論理的な推理で正解を絞り込みます。

---

## 2. ユーザーストーリー

| ID | ユーザーストーリー |
|----|------------------|
| US-01 | プレイヤーとして、5文字の単語を入力して推測できる |
| US-02 | プレイヤーとして、入力後に各文字の正誤が色で即座にわかる |
| US-03 | プレイヤーとして、仮想キーボードで打鍵済み文字の状態を把握できる |
| US-04 | プレイヤーとして、存在しない単語を入力したときにエラーフィードバックを受けられる |
| US-05 | プレイヤーとして、ゲーム終了時に正解単語の意味・解説を学べる |
| US-06 | プレイヤーとして、過去の勝率・連勝記録などの統計を確認できる |
| US-07 | プレイヤーとして、ゲーム終了後にリトライできる |
| US-08 | プレイヤーとして、物理キーボードと仮想キーボードの両方で快適に操作できる |

---

## 3. 機能要件

### 3.1 メインゲーム画面

#### 3.1.1 入力グリッド
- **FR-01:** 5列 × 6行のマス目グリッドを表示する
- **FR-02:** 現在入力中の行を視覚的に強調する
- **FR-03:** 1マスに1文字（A〜Z、大文字）を表示する
- **FR-04:** 回答確定後、各マスを正誤判定に応じた色に変化させる（フリップアニメーション付き）
  - 🟩 緑（Correct）: 文字・位置ともに正しい
  - 🟨 黄（Present）: 文字は含まれるが位置が違う
  - ⬛ 灰（Absent）: 単語に含まれない

#### 3.1.2 仮想キーボード
- **FR-05:** QWERTY配列の仮想キーボードを画面下部に表示する
- **FR-06:** Enter / Backspace キーを仮想キーボード上に配置する
- **FR-07:** 打鍵済みの文字キーに判定結果（緑/黄/灰）をリアルタイム反映する
  - 優先度: 緑 > 黄 > 灰（より高精度な情報を保持）

#### 3.1.3 物理キーボード入力
- **FR-08:** A〜Z キーで文字入力できる
- **FR-09:** Enter キーで単語を確定できる
- **FR-10:** Backspace キーで直前の文字を削除できる

### 3.2 ゲームロジック

- **FR-11:** ゲーム起動時、単語リストからランダムに1つのお題単語（5文字）を選択する
- **FR-12:** 入力された単語が単語リストに存在するか検証する（無効入力の拒否）
- **FR-13:** 5文字未満の状態でEnterを押した場合は入力不足エラーを表示する
- **FR-14:** 正解判定ロジックは重複文字を考慮した正確なWordle互換アルゴリズムを使用する
  - 例: お題が "ARRAY"、入力が "ALARM" → 1文字目 A=緑、2文字目 L=灰、3文字目 A=黄、4文字目 R=灰、5文字目 M=灰
- **FR-15:** 6回以内に正解 → 成功（Win）状態へ遷移する
- **FR-16:** 6回全て不正解 → 失敗（Lose）状態へ遷移する

### 3.3 結果ダイアログ

- **FR-17:** ゲーム終了時（Win/Lose）にモーダルダイアログを表示する
- **FR-18:** Win時は試行回数と称賛メッセージを表示する
- **FR-19:** Lose時は正解単語を大きく表示する
- **FR-20:** 正解単語のプログラミング的な意味・解説テキストを表示する
- **FR-21:** 統計情報（通算勝率、現在の連勝数、最高連勝数、試行回数分布）を表示する
- **FR-22:** 「もう一度遊ぶ」ボタンを押すと新しいゲームが始まる

### 3.4 統計・永続化

- **FR-23:** LocalStorageを使用してゲーム統計を保存・読み込みする
- **FR-24:** 保存する統計データ:
  - 総プレイ回数
  - 勝利回数
  - 現在の連勝数
  - 最高連勝数
  - 試行回数別の勝利分布（1〜6回）

## 4. 非機能要件

### 4.1 UI/UX

- **NFR-01:** ダークモードを基調としたデザイン（背景色: ほぼ黒〜濃いグレー）
- **NFR-02:** エンジニアライクでモダンな配色・フォント（等幅フォント採用）
- **NFR-03:** マスのフリップアニメーション（回答確定時）
- **NFR-04:** 不正入力時の振れ（シェイク）アニメーション
- **NFR-05:** キー押下時のスケールアニメーション
- **NFR-06:** 全アニメーションはスムーズで60fps以上を目標とする（CSS transform/opacity活用）

### 4.2 互換性・パフォーマンス

- **NFR-07:** モダンブラウザ（Chrome/Firefox/Safari/Edge 最新版）で動作する
- **NFR-08:** モバイルブラウザでも操作可能なレスポンシブデザイン
- **NFR-09:** 初回読み込みを3秒以内に完了する（本番ビルド時）

### 4.3 アクセシビリティ

- **NFR-10:** 各マス・キーに適切なaria属性を付与する
- **NFR-11:** 色覚多様性への配慮として、色に加えて記号や輝度差で状態を区別できる

---

## 5. 単語リスト要件

- **WL-01:** 5文字固定のプログラミング・IT関連英単語を最低50語収録する
- **WL-02:** お題候補単語（正解になりうる単語）は難易度を考慮して厳選する
- **WL-03:** 入力検証用単語リスト（有効単語リスト）はお題候補を包含する
- **WL-04:** 単語に対して意味・解説テキストを付与する（お題候補のみで可）

**単語例:**
`REACT`, `ARRAY`, `CLASS`, `ASYNC`, `AWAIT`, `STACK`, `QUEUE`, `PROXY`, `SWIFT`, `NUMPY`, `LINUX`, `CACHE`, `SCOPE`, `FETCH`, `YIELD`, `CONST`, `LOOPS`, `REGEX`, `MODAL`, `QUERY`

---

## 6. 制約・前提条件

- サーバーサイドは不要（完全クライアントサイドで完結）
- 外部APIへの依存なし（オフラインでも動作可能）
- 単語リストはクライアントバンドルに含める
